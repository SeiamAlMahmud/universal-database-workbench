Electron Build & Install Fix Guide
====================================
Project : murgiDB (universal-database-workbench)
Updated : 2026-03-08

This file documents every known startup/build issue and their fixes so that
any developer or AI assistant can reproduce a working build without repeating
the same debugging cycle.

=======================================================================
ISSUE 1 — "Renderer File Missing" (packaged / installed app)
=======================================================================

Symptoms
--------
- App opens a native error dialog:
    Title   : Renderer File Missing
    Message : Failed to load renderer file.
              Tried paths: ...app.asar\.vite\...index.html
              TypeError: Object has been destroyed
- The window is destroyed before the renderer can load.
- Only happens in the INSTALLED (packaged) app, not in `pnpm run start`.

Root Cause
----------
The `ignore` function in forge.config.ts used a *negative* (exclusion-only)
list that didn't explicitly protect the `.vite/` folder.
Electron Packager silently skips dot-folders (`.vite`, `.git`, etc.) unless
they are explicitly kept.  As a result the compiled renderer
(.vite/renderer/main_window/index.html) was ABSENT from the final package,
so every path candidate failed and the native error dialog appeared.

Fix Applied  →  forge.config.ts  (packagerConfig.ignore)
---------------------------------------------------------
❌ DO NOT use a custom ignore *function*.
   After reading @electron/packager/dist/copy-filter.js source directly,
   the packager passes paths as "/<relative>" strings to the filter.
   Any custom function that tries to handle cross-platform paths with
   __dirname, path.isAbsolute(), etc. will fail on CI in subtle ways.

✅ USE a regex ARRAY instead. The packager applies regex matching internally
   and handles all platform path differences automatically.

  // In packagerConfig:
  ignore: [
    '/src($|/)',
    '/\\.vscode($|/)',
    '/\\.github($|/)',
    '/\\.gitignore$',
    '/tsconfig.*\\.json$',
    '/vite\\..*\\.ts$',
    '/forge\\.config\\.ts$',
    '/eslint.*$',
    '/\\.eslint.*$',
    '/postcss\\.config.*$',
    '/tailwind\\.config.*$',
    '/README.*$',
  ],

⚠️  CRITICAL: Do NOT add .vite to this list. The packager already excludes
   .git, node_modules/.bin, pnpm-lock.yaml by default.

Root Cause Details (for future debugging):
  - @electron/packager validateElectronApp (common.js:102) checks:
      fs.pathExists(path.resolve(bundledAppDir, packageJSON.main))
  - If .vite/build/main/index.js is missing from bundledAppDir, it throws:
      "main entry point not found. Make sure ... does not get ignored"
  - The ignore option directly controls which files are copied to bundledAppDir.

ISSUE 2 — Blank / Black Screen on First Launch (Windows)
=======================================================================

Symptoms
--------
- App window appears but stays completely black/blank.
- Developer console shows cache errors:
    Unable to move the cache: Access is denied (0x5)
    Unable to create cache
    Gpu Cache Creation failed: -2

Root Cause
----------
Squirrel installer places the app in a read-only location under
%LOCALAPPDATA%.  Chromium tries to write its cache next to the executable
and fails with access denied, which prevents the renderer from rendering.

Fix Applied  →  src/main/index.ts  (top of file, before any BrowserWindow)
---------------------------------------------------------------------------
Force all runtime data into a writable per-user folder:

  const APP_DIR_NAME    = "murgiDB";
  const USER_DATA_PATH  = path.join(app.getPath("appData"), APP_DIR_NAME);
  const SESSION_DATA    = path.join(USER_DATA_PATH, "SessionData");
  const DISK_CACHE      = path.join(SESSION_DATA, "Cache");

  fs.mkdirSync(DISK_CACHE, { recursive: true });      // create eagerly
  app.setPath("userData",    USER_DATA_PATH);
  app.setPath("sessionData", SESSION_DATA);
  app.commandLine.appendSwitch("disk-cache-dir", DISK_CACHE);

These lines MUST run before app.on("ready") and before any BrowserWindow
is created.

Persistent data paths (after fix):
  userData    → %APPDATA%\murgiDB
  sessionData → %APPDATA%\murgiDB\SessionData
  cache       → %APPDATA%\murgiDB\SessionData\Cache
  connections → %APPDATA%\murgiDB\connections.json

ISSUE 3 — Silent Crash (no error shown to user)
=======================================================================

Fix Applied  →  src/main/index.ts
----------------------------------
1. Wrap loadFile/loadURL in .catch() and call showErrorBox on failure.
2. Listen to did-fail-load and render-process-gone events and show a
   visible dialog so the user is never left with a silent blank window.
3. Guard all renderer-load code with mainWindow.isDestroyed() to avoid
   "Object has been destroyed" secondary errors.

ISSUE 4 — native module (better-sqlite3) fails in packaged app
=======================================================================

Symptoms
--------
- "A JavaScript error occurred in the main process" dialog.
- Error mentions MODULE_NOT_FOUND or a .node binary not found.

Fix Applied  →  forge.config.ts  (packagerConfig.asar)
-------------------------------------------------------
  asar: {
    unpack: "{**/node_modules/better-sqlite3/**,**/node_modules/bindings/**,**/*.node}",
  },

And add the AutoUnpackNativesPlugin:
  plugins: [
    new AutoUnpackNativesPlugin({}),
    ...
  ]

Also keep adapters lazily loaded via require() (not top-level import) so
that a missing native dependency throws a catchable error at runtime rather
than crashing the whole main process at startup.

=======================================================================
HOW TO BUILD A CORRECT INSTALLER
=======================================================================

Prerequisites
-------------
- Node.js 20+
- pnpm  (npm i -g pnpm)
- Windows: WiX Toolset v3.11 for .msi (optional, Squirrel .exe works without it)

Steps
-----
1. Clean old outputs:
     Remove-Item -Recurse -Force out, .vite

2. Install dependencies:
     pnpm install

3. Rebuild native modules for the current Electron version:
     pnpm exec electron-rebuild   (or handled automatically by Forge)

4. Build installer:
     pnpm run make

5. Output location:
     out\make\squirrel.windows\x64\murgidbSetup.exe   (Squirrel)
     out\make\wix\x64\murgiDB-*.msi                   (WiX, if available)

6. Before installing the new build, remove old install data:
     %APPDATA%\murgiDB
     %LOCALAPPDATA%\murgiDB
     %APPDATA%\DB Workbench        ← old name, if present

DEV ENVIRONMENT ISSUES
=======================================================================

Electron binary not found / failed to install
----------------------------------------------
  node node_modules\electron\install.js
  Get-Content node_modules\electron\path.txt
  Test-Path node_modules\electron\dist\electron.exe
  pnpm run start

Full reset (last resort)
------------------------
  Remove-Item -Recurse -Force node_modules
  Remove-Item -Force pnpm-lock.yaml
  pnpm install
  pnpm run make

=======================================================================
NOTES FOR AI ASSISTANTS
=======================================================================

- The main entry point declared in package.json is:
    ".vite/build/main/index.js"
  This is compiled by Electron Forge's Vite plugin. Do NOT change it.

- Renderer path at runtime (production):
    __dirname = .vite/build/main/
    Correct index.html → .vite/build/main/../../renderer/main_window/index.html
                       = .vite/renderer/main_window/index.html

- The forge.config.ts ignore function must EXPLICITLY keep ".vite/" or the
  renderer will be missing from the package. This is the most common
  mistake and the hardest to debug because it only fails in production.

- MAIN_WINDOW_VITE_NAME is injected by the Vite plugin at build time
  and equals the `name` field of the renderer entry in forge.config.ts
  (currently "main_window").

- Do NOT add top-level static imports for native modules (better-sqlite3,
  etc.) in any file that is included in the main bundle. Use require()
  inside a function so failures are catchable.
